## How I work

- **Make the claim inspectable.** Architecture, assumptions, limitations, and trust boundaries belong in the product—not only in a presentation.
- **Keep intelligence testable.** I prefer deterministic domain logic, reproducible fixtures, and explicit evaluation over opaque demos.
- **Design for real operators.** Accessibility, mobile behavior, failure states, privacy, and offline constraints are engineering requirements.
- **Ship with proof.** Tests, static analysis, security checks, CI, documentation, and reviewable commits are part of the feature.
- **Be honest about prototypes.** Synthetic data, simulations, and unimplemented production gates should be labeled clearly.
